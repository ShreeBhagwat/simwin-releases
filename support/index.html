Support

Get help with SimWin

Start with simwin doctor or the Doctor tab in SimWin: it checks everything SimWin needs and gives a fix for each problem. If that doesn’t help, tell us.

Report a problem

From the app (best): choose Help ▸ Report a Problem… (also in the menu bar icon and the Doctor tab). Describe what happened, then:

  • Email Support opens a new email to support@codeaamy.com in your mail app, with a diagnostics file attached.
  • Open GitHub Issue opens a public issue with your description and the setup summary, without the logs.

Nothing is sent until you send it yourself.

From Terminal: simwin report creates the same diagnostics file and prints where it is.

Without the app: email support@codeaamy.com or open a GitHub issue.

What the diagnostics file contains

  • SimWin, macOS and Flutter versions, and whether your Mac is Apple Silicon or Intel.
  • The results of SimWin’s setup checks (the same as simwin doctor).
  • SimWin’s build and app logs from the last week, at most 256 KB each.

It never includes your project’s source code. Your home folder is shortened to ~ in every path. You can look inside before sending: click Show in the report window.

What helps us fix it fastest

  • What you did, what you expected, and what happened instead.
  • For build problems: which plugins your app uses (your pubspec.yaml dependencies).
  • A screenshot if something looks wrong.

Troubleshooting

“SimWin · Windows 11” isn’t in my IDE’s device list

Open SimWin once (it re-registers itself if you moved the app), or run simwin setup --register. Then restart the IDE’s device scan: in VS Code, run Flutter: Select Device; in Android Studio, reopen the device list. flutter devices should list it. If it says custom devices are disabled, run flutter config --enable-custom-devices.

The build fails

The error in your IDE says what failed and how to fix it. Most often it’s a plugin that needs Visual Studio-only tools; SimWin leaves those out and lists them, so check whether your app needs that plugin to start. For anything else, report it: build logs are in ~/Library/Logs/SimWin, and the problem report includes them.

SimWin warns about my Flutter version

SimWin is tested with stable 3.45 – 3.47. Other versions often work, but if yours doesn’t, switch to a tested version with flutter upgrade or flutter downgrade.

The app window doesn’t appear

Check the SimWin menu bar icon: it shows whether the app is building or running. Look on other Spaces and displays too. Run simwin doctor and fix anything marked ✗. On Apple Silicon, Rosetta 2 must be installed.

Screenshots or recordings are black or fail

Allow SimWin in System Settings ▸ Privacy & Security ▸ Screen & System Audio Recording, then quit and reopen SimWin. After an update you may need to switch it off and on again.

The first build is slow

That’s expected: SimWin fetches Flutter’s Windows engine files for your Flutter version and compiles everything once. Later builds are incremental.

Text or dialogs look slightly different from Windows

Your app runs under a compatibility layer, not Windows itself, so fonts and system dialogs (file pickers, printing) can differ. Check final visuals on a real Windows PC.

Feature requests

Choose Help ▸ Send Feedback… in SimWin, or email us. We’d especially like to hear which plugins you need.
