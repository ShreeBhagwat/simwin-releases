What SimWin does

Everything you need to check your Windows app, without leaving your Mac

Catch layout, scaling, keyboard and platform-specific bugs in the Windows version of your app while you build it, not after someone tries it on a PC.

The real Windows build

Your app is compiled for Windows x64 on your Mac. Platform.isWindows is true, paths are C:\…, and your Windows plugin code runs.

A device in your IDE

“SimWin · Windows 11” appears in the device list of VS Code, Android Studio and flutter devices, just like an emulator.

Hot reload and DevTools

Debug mode with hot reload, hot restart, breakpoints and Flutter DevTools, exactly as on a Windows PC.

Simulator toolbar

Switch display scale (100–200 %), window size, light or dark mode and locale, including right-to-left languages.

Screenshots and recordings

Capture the app window as PNG or record it as video, from the toolbar, the menu bar or the command line.

Profiles

Save combinations of scale, size, theme and locale, and switch between them in one click.

Plugins that compile

Windows plugin code is compiled with clang. Plugins that need Visual Studio-only tooling are detected and named, not left to fail silently.

Command line

simwin open, simwin screenshot and simwin doctor work in Terminal and scripts, without an IDE.

Your project stays untouched

SimWin builds from a private copy of your project. It never edits your files, pubspec or Git state.

How it works

Three steps for you. A Windows toolchain for SimWin.

  1. 1

    Install and set up

    Drag SimWin to Applications and open it. Setup downloads the build tools (about 400 MB) and checks everything with a sample app. About five minutes, once.

  2. 2

    Pick the device

    Open your Flutter project in VS Code or Android Studio and choose “SimWin · Windows 11” from the device list.

  3. 3

    Press Run

    SimWin builds the Windows app and opens it in its window. Edit your code and hot reload as usual.

    my_app.exe

  4. Step 4

    Runs on your Mac

    through Wine, a compatibility layer (not a VM); graphics via DXVK → MoltenVK → Metal

    →
  5. Step 5

    Connected to your IDE

    the Dart VM service: hot reload, breakpoints, DevTools

The first build of a project takes a few minutes (SimWin fetches Flutter’s Windows engine files and compiles everything). After that, builds are incremental and hot reload takes well under a second.

Good to know

What SimWin is, and what it isn’t

Not a replacement for a final check on Windows

It is your real Windows build running under a compatibility layer, not Windows itself. Fonts, system dialogs (file pickers, printing) and some Win32 APIs can differ. Test on a real PC before you release.

Debug builds only

Release and profile builds need Windows-only tools, so build the .exe you ship on Windows or in CI.

Visual Studio-only plugins

Plugins that need C++/WinRT, MFC, ATL, NuGet packages or WebView2 aren’t supported yet. SimWin leaves them out of the build and tells you which ones.

Speed on Apple Silicon

Windows x64 code runs through Rosetta 2. That’s fine for UI work and debugging, not for benchmarking.

FAQ

Questions developers ask

Is this a virtual machine?+
No. SimWin doesn’t install or run Windows. It compiles your app for Windows and runs the .exe directly on macOS through Wine, a compatibility layer that translates Windows calls to macOS ones. That is why it starts in seconds and uses far less memory than a VM.
Do I need a Windows PC or a Windows licence?+
No. Everything is built and run on your Mac. You don’t need Visual Studio either.
Does SimWin change my project?+
Never. It builds from a private copy of your project in ~/Library/Caches/SimWin, and that is where any compatibility fixes are applied. Your files, pubspec and Git state are left exactly as they were.
Can I build the .exe I ship to users?+
Not yet. SimWin makes debug builds for testing. Release builds need Windows-only tools, so build them on Windows or in CI.
Which plugins work?+
Plugins whose Windows code is ordinary C++ work, such as path_provider, shared_preferences, url_launcher and package_info_plus. Plugins that need Visual Studio-only features (C++/WinRT, MFC, ATL, NuGet, WebView2) are left out of the build, and SimWin tells you which ones, so the rest of your app still runs.
Which Flutter versions are supported?+
The stable channel: the newest tested version and the two before it (currently 3.45 – 3.47). SimWin always uses the Flutter SDK your IDE runs. Other versions usually work too; SimWin warns you if yours is outside the tested range.
Does it work on Apple Silicon?+
Yes. Windows x64 code runs through Rosetta 2, which setup installs if needed. Intel Macs run it natively.
Does SimWin collect any data?+
No analytics and no tracking. SimWin only goes online to download its build tools during setup, to fetch Flutter’s Windows engine files from Google, and to check for updates. Problem reports are sent by you, from your own mail app. See the privacy page.
How do I uninstall it?+
Follow these steps: remove the IDE device, delete the app and delete SimWin’s three folders in your Library.
